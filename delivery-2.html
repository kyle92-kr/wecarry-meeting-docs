위캐리 AX 버전 2 · 2차 납품 안내

요청을 계획표로, 승인한 계획을 일시중지 광고로.

관리자는 연결과 권한을 준비하고, 마케터는 계획표와 실행 승인을 확인합니다. 광고를 켜는 일은 각 광고 관리자에서 사람이 직접 합니다.

버전·상태 — 버전 2(v2.1.0) · 현재 후보 v2.1.0-rc.4 · 최종 확정 전

문서 기준 2026-11-15 · 대면 설정 예정 2026-11-17 · 광고 세팅 스킬 v0.4 + 영상 검수 스킬 v0.1 + Google 확장 0.2.0.

버전 1은 v2.0.0-alpha.2(1차 납품본), 버전 2는 v2.1.0이며 현재는 rc.4 사전 후보입니다. 버전 1 기록은 보존합니다.

전달 상태: 버전 2 (v2.1.0-rc.4) 하위 폴더에 스킬 2개·확장·SHA256SUMS를 제공합니다. 후보 rc.4, 재시험 후 v2.1.0 확정 시 교체될 수 있음. 상위 폴더의 기존 alpha.2 파일은 버전 1로 보존합니다. 파일 제공은 실기 재시험 통과를 뜻하지 않으며 비공개 GitHub 릴리스는 고객 다운로드 경로가 아닙니다.

Windows 확인: 조회·꼬리표 중복 멈춤·UTM만 생성 0회, 분리 후 영상 검수, Google 두 테스트 계정 분리 조회/생성, 요청 3건의 생성·재조회 기록이 있습니다. 각 rc.1/rc.2 조건의 결과이며 rc.4 전체 합격은 아닙니다.

남은 확인: rc.4 숫자만 승인 거부·값 변경 재승인·새 보고 형식, Mac Cowork, Slack 내부 채널 실제 전송, 위캐리 환경·카페24 집계·Team 조직 배포·파일 교체. rc.2의 승인 위반과 앱 승인 창 거절 사례도 3절에 표시했습니다.

화면 안내: Cowork 홈 입력창 합병은 보도 기준(공식 공지 미확인)입니다. 프로젝트 폴더 경로는 Windows 실측, 최신 앱·Mac 메뉴는 확인 필요입니다. 이 문서는 최종 납품 수락 기록이 아닙니다.

01

관리자 설치 안내서

위캐리 Owner가 준비합니다. 버전 2 파일이 전달된 뒤 아래 5단계를 확인합니다.

01 · 스킬 2개 설치와 Owner 확인

  • 광고 세팅 wecarry-ad-setup v0.4, 영상 검수 wecarry-creative-check v0.1을 각각 등록합니다. 영상 검수 zip도 별도로 필요합니다.
  • 기존 1차 파일과 섞지 말고 전달본 버전을 확인합니다. Windows 개인 계정 설치는 기록됐으며 Team Owner 조직 배포 메뉴·권한은 확인 필요입니다.

02 · 공식 연결과 프로젝트 소재 폴더

  • Notion·Google Drive·Slack·Meta Ads·TikTok for Business를 본인 계정으로 연결하고 브랜드별 자료·광고 계정·페이지 접근 권한을 확인합니다. 메뉴 위치는 확인 필요입니다.
  • Cowork 프로젝트 “컨텍스트 → 추가 → 로컬 폴더 연결”로 필요한 폴더만 등록합니다. 입력창 “폴더 추가”는 일회성입니다. Windows 경로 기준이며 Mac은 확인 필요입니다.
  • 검수 파일은 Anthropic 서버 작업 공간으로 넘어갑니다. OneDrive 등 동기화 위치를 확인하고 고객 소재는 비동기화 업무 폴더를 권장합니다.
  • 브랜드별 내부 Slack 채널, Meta 공식 연결(Ads MCP) 자체와 업로드 URL 도구가 열리는지 각각 확인합니다.

03 · 수동 모드와 위험 도구 차단

  • TikTok 상태 변경(*_status_update)·수정(*_update)·예산 변경·bc_create, Meta 켜기(Activate Ads Entity)·수정(Ads update entity)·인스타 홍보(Ads boost ig post)를 차단합니다.
  • 생성 도구·TikTok tool_execute는 승인 필요입니다. 안의 상태 변경·수정·예산 변경·삭제는 허용하지 않습니다.
  • 수동 모드·항상 허용 금지를 유지합니다. 스킬이 규칙을 어겨 진행한 rc.2 시도를 앱 승인 창에서 거절해 막은 기록이 있습니다. 설정 경로는 확인 필요입니다.

04 · Google 준비와 비밀값 보관

  • 위캐리 Workspace 하위 Cloud 프로젝트·Google Ads API·내부용 OAuth·데스크톱 클라이언트를 준비하고 Explorer 등급을 신청합니다. 실제 고객 환경·화면 경로는 확인 필요입니다.
  • OAuth client secret은 재설치 때 재입력합니다. 관리자는 발급 즉시 비밀번호 관리자 등 안전한 저장소에 보관합니다. Google에서 기존 전체 값을 재조회할 수 없고 새 secret을 추가할 수 있습니다.
  • 비밀값은 확장 설정에만 입력하며 채팅·Notion·Slack·문서에 붙이지 않습니다. 마케터 패스키 지연 가능성도 확인합니다.

05 · Google 확장 0.2.0 설정·재시작

  • 버전 2 전달본 .mcpb를 설치합니다. Google Ads customer ID (optional)에 값이 있으면 고정 모드, 비우면 다계정 모드입니다. 비워도 계정 접근 권한이 자동으로 생기지 않습니다.
  • 다계정은 호출마다 브랜드 customerId가 필요하며 마지막 계정으로 대체하지 않습니다. Manager (MCC) customer ID는 경유할 때만 입력하고 설정은 하나입니다. 같은 MCC 아래 브랜드들인지 확인합니다.
  • OAuth client ID·OAuth client secret을 설정합니다. 설정 변경 후 앱 완전 종료·재시작하고 “구글 로그인”·상태 조회를 합니다. 관리자 계정 자체 생성은 거절합니다.
  • 계정 이름·번호·모드를 브랜드와 대조합니다. 최신 설치 화면·Mac·위캐리 실제 계정의 확인은 남아 있습니다.
02

마케터 사용 안내서

Cowork에서 사용합니다. 계획표 승인과 앱 도구 승인 창은 별개입니다.

01 · 설치·로그인·소재 폴더 확인

  • 버전 2 스킬 2개와 확장 0.2.0 전달본을 설치하고 새 Cowork 대화에서 “구글 로그인”, 인증 뒤 “로그인 상태 확인”을 요청합니다. Code·웹은 Google 확장 대상이 아닙니다.
  • 프로젝트 “컨텍스트 → 추가 → 로컬 폴더 연결”을 확인합니다. 검사 파일은 서버 작업 공간으로 넘어갑니다. 앱이 “내 컴퓨터에서 명령어 실행함”이라고 표시해도 영상 측정은 서버에서 실행됩니다.
  • 설정을 바꿨다면 앱을 완전히 종료·재시작합니다. 패스키·로그인 문제는 관리자와 확인합니다.

02 · 요청 문장 예

  • 여러 요청: Notion 주소들과 함께 “이 요청 세 건 세팅해 줘.” 요청 목록과 1·2·3 라벨·브랜드를 확인합니다.
  • UTM만: “이 요청 UTM 만들어 줘.” 출처와 링크 표를 확인합니다. 같은 대화에서 “이어서 세팅해 줘”라고 해도 광고 계획표 승인은 따로 필요합니다.
  • 영상 검수: “이 영상들 문제없는지 봐 줘.” 별도 영상 검수 스킬의 판정·시점·자막 원문·검사 범위를 확인합니다. “이상 없음”은 필수 치명 검수·광고 승인을 대신하지 않습니다.
  • 브랜드가 바뀌면 계정·페이지·타기팅·예산·Slack 채널을 새로 확인합니다. 같은 요청 담당을 팀에서 나눕니다.

03 · 마지막 계획표에 “1 승인”

  • 요청별 계정·소재·문안·랜딩/UTM·타기팅·일정·예산·검수·부모·건너뜀을 확인합니다. Google은 브랜드 계정 이름·번호·모드, Meta는 Advantage+·결제 기준·썸네일·Instagram 연결도 확인합니다.
  • 표시 라벨과 “승인”을 함께 답합니다(“1 승인”, “2 승인”). 숫자만·“네”·“진행”·“좋아요”·“제안대로”는 생성 승인이 아닙니다. 라벨 없는 일괄 승인은 다시 확인합니다.
  • 값이 바뀌거나 새로 정해지면 전후 표와 수정된 계획표 전체를 다시 확인하고 해당 라벨을 재승인합니다. 요청 2 변경은 요청 1·3 승인에 영향을 주지 않습니다.
  • 예산은 사람이 정합니다. Google 금액이 없으면 생성하지 않습니다. TikTok Spark는 비활성이어도 브랜드 계정에 광고 전용 게시물이 생기는 점을 확인합니다.

04 · 앱 승인 창에서 실행 확인

  • 수동 모드·항상 허용 금지를 유지합니다. 승인한 계정·계획과 다른 실행은 거절합니다. 자동 허용은 화면과 무관한 사용자 설정입니다.
  • Meta·Google은 PAUSED, TikTok 캠페인·광고그룹·광고는 모두 operation_status: "DISABLE"인지 확인합니다. ENABLE·값 누락·판단 불가면 허용하지 않습니다.
  • tool_execute 안의 도구 이름을 확인합니다. 켜기·수정·예산 변경·삭제·이름 불명 실행은 허용하지 않습니다.
  • 일반 파일 읽기·검수 명령은 창 없이 실행된 반면 위험한 정리에는 승인 창이 뜬 기록도 있습니다. 커넥터 승인과 서버 작업을 구분합니다.

05 · 결과 표와 업로드 대안

  • 요청별 상태 표에서 생성·예산 대기·실패·다음 행동을 확인합니다. 결과의 매체·이름·전체 ID·상태·링크를 확인하고 Slack 실제 전송과 초안을 구분합니다.
  • Meta 선택 창이 안 보이면 “창이 안 보입니다”라고 알려 줍니다. 수동 업로드는 계획표 광고 계정을 선택해 미디어 라이브러리 “광고 계정 미디어”에 올립니다. “비즈니스 미디어”는 다른 메뉴입니다.
  • 이미 올린 소재도 이미지·썸네일을 보고 짝을 확인합니다. 파일·버튼·Instagram·자동 소재 개선 등 계획값이 바뀌면 다시 승인합니다.
  • 생성 결과가 불확실하면 반복 생성 전에 재조회합니다. 켜기 전 Google 지역·Meta 광고 게재 주체 인증을 확인합니다. 켜기·예산 변경은 각 광고 관리자에서 사람이 직접 합니다.

공통·Cowork

  • Notion 기존 구조를 읽고 없는 값은 묻습니다. 후보 하나도 임의로 고르지 않습니다. 패스워드 칸·비밀값을 대화·보고로 옮기지 않고 Notion의 세팅 기록을 바꾸지 않습니다.
  • Drive 소재를 공개로 바꾸지 않습니다. 영상 검수는 연결 폴더에 결과를 쓰지 않고 서버 임시 작업 공간을 사용합니다. 앱 실행 위치 문구와 실제 서버를 구분합니다. 이번 VM 2코어·7.8GB는 관찰값이며 고정 사양이 아닙니다.
  • 영상 선택 리포트는 요청할 때만 실행합니다. 필수 치명 검수(앞뒤 검은 화면 0.5초 이상·전체 검정·깨짐)는 별개로 유지하며 자막을 자동 수정하지 않습니다.
  • 같은 요청 동시 실행은 팀에서 담당을 나눕니다. 생성 직전 태그 중복 조회·불확실 결과 재조회를 유지하고 기존 광고는 자동으로 수정·삭제하지 않습니다.

Google

  • 고정 모드는 설정 계정만, 다계정은 호출마다 브랜드 customerId입니다. 관리자 계정 생성은 거절하며 설정 MCC는 하나입니다. 조회 0건의 allPaused=null은 해당 없음, 생성 직후 재조회 0건은 검증 미확인으로 구분합니다.
  • EU 정치광고 미포함·검색 네트워크만·디스플레이/검색 파트너 끔·새 비공유 예산으로 생성합니다. 일예산·CPC 입찰가가 없으면 Google은 생성하지 않습니다.
  • 지역·언어는 확장이 지정하지 않습니다. 켜기 전 지역을 확인합니다. 계정 링크 대신 이동 경로와 전체 식별값으로 찾으며 SERVING이 함께 보여도 PAUSED와 구분합니다.
  • 재설치용 secret은 관리자가 안전하게 보관하고 설정 변경 뒤 앱 완전 종료·재시작을 합니다. Google secret 관리 안내.

Meta·TikTok·Slack

  • Meta는 공식 연결 자체와 업로드 도구가 브랜드 계정별로 다를 수 있습니다. 도구 응답만으로 선택 창이 열렸다고 판단하지 않습니다. 수동 업로드 메뉴는 광고 계정 미디어이며 비즈니스 미디어와 다릅니다.
  • Meta 이미지 기본 1장=광고 1개, 요청이 캐러셀일 때만 묶습니다. Advantage+·결제 기준·영상 썸네일·버튼·Instagram·자동 소재 개선을 표에서 확인합니다. IN_PROCESS는 검토 중이며 켜기 전 게재 주체 인증을 확인합니다. 복제·새 로컬 업로드 지원은 확인 전입니다.
  • TikTok은 세 단계 DISABLE을 보장할 수 없으면 생성하지 않습니다. 브랜드 TikTok 계정의 Business Center 연결·광고 계정 할당이 필요합니다. Smart+ 영상 Spark 외 캐러셀/다른 identity/예산 경로와 최신 rc.4 전체 흐름은 확인 필요입니다.
  • Slack은 브랜드마다 내부 채널을 확정합니다. 외부 공유(Slack Connect) 실패는 초안으로 대체하고 위치·실패 이유를 알립니다. 초안 저장은 실제 전송이 아닙니다.

UTM

  • 요청·브랜드 시트에 명시된 값·완성 링크가 있으면 출처와 함께 그대로 쓰고 충돌은 묻습니다. 없을 때만 카페24 규칙으로 생성합니다. medium은 유형이며 매체별 값은 확인받습니다.
  • 규칙에 없는 파라미터는 값을 받거나 그 파라미터만 빼기를 마케터가 선택하고 표에 표시합니다. 기존 쿼리를 보존하며 중복 키는 묻고 Meta URL/url_tags 한 곳만 사용합니다.
  • ATMS 링크에 임의 UTM을 덧붙이지 않고 nt_는 형식 확인 전 만들지 않습니다. Instagram 미연결이면 utm_source와 게재 영향을 표에서 질문합니다.
  • 카페24 공식 안내는 URL UTM 자동 분석을 안내하지만 위캐리 실제 집계는 확인 전입니다. 매니저 자동 등록은 하지 않습니다.

납품 미팅 안건

01 · Google 계정·설치와 비밀값

  • 브랜드 계정들이 같은 MCC 아래인지, 본인 로그인 접근 범위와 고정/다계정 모드·공유 예산 사용 여부를 정합니다.
  • 재설치용 secret 보관 담당·안전한 저장소·설정 변경 후 재시작 절차를 확인합니다. 내부용 앱·Explorer·패스키는 실제 환경에서 확인합니다.

02 · Meta 공식 연결·업로드·Instagram

  • ⑬ 브랜드마다 Ads MCP 공식 연결 자체와 업로드 URL 도구가 열리는지 각각 확인합니다. 파일 선택 창 미표시 때 광고 계정 미디어 대안을 확인합니다.
  • ⑭ 비즈니스 미디어와 광고 계정 미디어 메뉴를 구분합니다. 실제 고객 화면은 현장에서 확인합니다.
  • ⑫ Instagram 미연결 계정의 utm_source와 Instagram 게재 위치 적용 기준을 정합니다. 타기팅·Advantage+·결제 기준·버튼·자동 소재 개선 기본값도 확인합니다.

03 · Slack 보고·권한·협업

  • ⑦ 브랜드별 내부 보고 채널을 지정합니다. 외부 공유 채널 실패는 초안 저장이며 내부 실제 전송은 미실시임을 확인합니다.
  • 계정 정보 패스워드 칸 비노출 권한, 프로젝트 폴더 범위·서버 전송, 동기화 위치·요청 담당 분담을 정합니다.

04 · UTM과 기존 업무 규칙

  • U1 항상/브랜드 요청 시만 부착 범위, U2 매체별 medium·TikTok/Kakao 접두어, U3 소재번호·세트명·날짜 원천 칸과 형식.
  • U4 ATMS 브랜드 목록·처리, U6 스마트스토어 nt_ 형식. U5는 공식 근거와 별개로 위캐리 실제 집계를 확인합니다.
  • 이름 날짜·구분자, Drive 링크 범위, 사용 여부 꺼진 행, 일정 31일 해석을 확인합니다. 확인하지 않은 값은 지어내지 않습니다.
