위캐리 AX v2.1 · 1차 납품 안내

요청을 계획표로, 승인한 계획을 일시중지 광고로.

관리자는 연결과 권한을 준비하고, 마케터는 계획표와 실행 승인을 확인합니다. 광고를 켜는 일은 각 광고 관리자에서 사람이 직접 합니다.

버전·상태 — 안내서 v2.1 · 1차 납품본(v2.0.0-alpha.2), 실기 재확인 전

문서 개정일 2026-11-15 · 대면 설정 예정 2026-11-17 · 스킬 v0.3·Google 확장 0.2.0 기준 안내(PR #16·#15, 검토 중).

파일과 문서 버전: 아래 다운로드와 SHA256은 기존 alpha.2 파일입니다. 새 스킬·확장은 11/17 W7에서 교체 예정이며 아래 파일을 설치하면 새 기능이 들어 있다고 보장하지 않습니다. 최신 파일 전달·설치 후 확인합니다.

확인된 범위: 기존 Windows Chat에서 매체별 일시중지/비활성 생성·재조회 기록이 있습니다. Windows Cowork A1~A7에서는 기존 Google 확장 노출·로그인 상태·조회, 공식 커넥터, 연결 폴더 읽기·정상/검은 화면 합성 영상 필수 검수, 스킬의 중복 발견 후 생성 0회를 확인했습니다. 새 Google 로그인은 미실시입니다.

확인 필요: Mac Cowork, 최신 확장 재설치와 Google 2계정 교차·브랜드 대조, “A 승인” 재시험, 영상 선택 리포트 전체, 위캐리 카페24 집계·실제 광고 계정 전환·내부용 앱·Explorer·조직 배포·Slack 내부 전송. 기존 시험을 새 버전 통합 합격으로 표시하지 않습니다.

화면 안내: 기본은 Cowork입니다. 홈 입력창 합병은 보도 기준(공식 공지 미확인)이며 화면 위치는 앱·OS별 재확인 대상입니다. 프로젝트 폴더 경로는 Windows 실측을 따릅니다. 최종 납품 수락 기록은 아닙니다.

01

관리자 설치 안내서

위캐리 Owner가 준비합니다. 5단계 이후 마케터와 Cowork에서 연결 상태를 확인합니다.

01 · Owner 지정과 스킬 등록

  • Claude Team Owner를 지정하고 스킬 v0.3 전달본을 조직에 등록합니다. 현재 폴더 파일은 W7 교체 전이므로 버전을 먼저 확인합니다.
  • 조직 등록 메뉴·배포 동작은 확인 필요입니다. 마케터의 새 Cowork 대화에서 “이 요청 세팅해 줘”가 스킬로 처리되는지 확인합니다.

02 · 공식 연결과 소재 폴더 준비

  • Notion·Google Drive·Slack·Meta Ads·TikTok for Business를 본인 계정으로 연결합니다. 메뉴 위치는 확인 필요입니다.
  • 브랜드마다 광고 계정·페이지·자료 권한과 내부 Slack 채널을 확인합니다. Meta 공식 연결 자체와 업로드 도구가 브랜드 계정별로 열려 있는지 각각 확인합니다.
  • Cowork 프로젝트 화면 “컨텍스트 → 추가 → 로컬 폴더 연결”로 필요한 업무 소재 폴더를 등록합니다(Windows 실측, Mac 확인 필요). 입력창 “폴더 추가”는 일회성입니다.
  • 검사 파일은 Anthropic 서버 격리 작업 공간으로 넘어가고 파일 읽기·작업 공간 명령에는 승인 창이 없습니다. OneDrive 등 동기화 여부를 보고 고객 소재는 비동기화 폴더를 권장합니다.

03 · 위험 도구 차단과 실행 승인 설정

  • TikTok의 상태 변경(*_status_update)·수정(*_update)·예산 변경·bc_create 도구를 차단합니다.
  • tool_execute는 승인 필요로 두며 안의 상태 변경·수정·예산 변경·삭제는 허용하지 않습니다.
  • Meta Activate Ads Entity·Ads update entity·Ads boost ig post를 차단합니다.
  • 수동 모드·항상 허용 금지를 유지합니다. 자동 허용은 Chat/Cowork와 무관한 사용자 설정입니다. 설정 메뉴는 확인 필요입니다.

04 · 위캐리 Google Cloud 준비

  • 위캐리 Workspace 하위 Cloud 프로젝트에서 Google Ads API·내부용 OAuth 앱·adwords 범위·데스크톱 OAuth 클라이언트를 준비합니다. 화면 경로는 확인 필요입니다.
  • Google Ads API Explorer 등급을 신청하고 상태를 확인합니다. 실제 계정 사용·내부용 앱은 위캐리에서 확인 필요, 심사 소요 시간은 미공개입니다.
  • 비밀값은 확장 설정에만 입력하며 채팅·문서·Notion·Slack에 붙이지 않습니다.

05 · Google 확장 0.2.0 전달 후 모드 설정

  • W7에서 전달할 0.2.0 .mcpb를 설치합니다. 아래 기존 다운로드가 교체되기 전에는 최신 파일인지 납품 담당자와 확인합니다.
  • Google Ads customer ID (optional)는 선택 항목입니다. 입력하면 그 계정만 쓰는 고정 모드, 비우면 호출마다 브랜드 계정이 필요한 다계정 모드입니다.
  • Manager (MCC) customer ID는 경유할 때만 입력하며 설정 1개를 공유합니다. 브랜드들이 같은 MCC 아래인지 확인합니다. MCC 자체에는 광고를 만들지 않습니다.
  • OAuth client ID·OAuth client secret은 설치 설정에 입력합니다. 최신 화면·Mac 설치는 확인 필요입니다.
  • Cowork에서 로그인·계정 이름·끝 4자리·모드를 대조하고 승인 창을 확인합니다. 위캐리 매체별 생성·재조회는 당일 시험으로 남깁니다.
02

마케터 사용 안내서

Claude 데스크톱 앱의 Cowork에서 사용합니다. 새 기능은 스킬 v0.3·확장 0.2.0 설치 후 이용하며 계획표 승인과 도구 실행 확인은 별개입니다.

01 · 확장 설치·로그인·프로젝트 폴더

  • 전달본 버전을 확인하고 .mcpb 설치 설정을 관리자와 맞춥니다. 설정 칸을 비웠다고 브랜드 계정이나 접근 권한이 자동으로 생기지는 않습니다.
  • Cowork에서 “구글 로그인”을 입력하고 브라우저 인증 후 “로그인 상태 확인”을 요청합니다. Cowork 새 로그인 실기는 확인 필요입니다. Code·웹은 확장 사용 대상이 아닙니다.
  • 프로젝트 “컨텍스트 → 추가 → 로컬 폴더 연결”을 사용합니다. 입력창 “폴더 추가”는 일회성입니다. 필요한 폴더만 연결하고 서버로 검사 파일이 넘어가는 점을 확인합니다.
  • 패스키 지연은 관리자에게 알리고 해제 후 로그인합니다. 폴더 자동 연결은 위캐리 PC·Mac에서 확인 필요입니다.

02 · 요청·UTM·영상 검수 전달

  • Notion 주소와 “이 요청 세팅해 줘” 또는 “이 요청들 세팅해 줘”라고 입력합니다. 여러 요청은 목록과 A·B·C 라벨을 먼저 확인합니다.
  • 브랜드가 바뀌면 계정·페이지·타기팅·예산·Slack 채널을 새로 확인합니다. 앞 브랜드 값을 이월하지 않습니다. 팀에서 같은 요청 담당을 나눕니다.
  • UTM 예: “이 요청 UTM 만들어 줘.” 링크 표의 값·출처를 확인하고 같은 대화에서 “이어서 세팅해 줘”라고 합니다. UTM 표 확인만으로 광고는 만들지 않습니다.
  • 영상 예: “이 요청 영상들 문제없는지 봐 줘.” 판정·발견 시점·자막 원문·검사 범위를 확인합니다. 선택 리포트의 “이상 없음”도 필수 치명 검수와 계획표 승인을 대신하지 않습니다.

03 · 계획표 확인 후 “A 승인”

  • 요청별 계정·소재·문안·랜딩/UTM·일정·예산·검수·건너뜀·생성 방식/부모를 확인합니다. Google은 계정 이름·끝 4자리·고정/다계정 모드·MCC 경유를 대조합니다.
  • 예산은 사람이 정하며 Google 금액이 없으면 생성하지 않습니다. TikTok Spark는 비활성이어도 브랜드 계정에 광고 전용 게시물이 생기는 점을 확인합니다.
  • 여러 요청은 “A 승인”처럼 하나씩 승인합니다. A만 승인하면 B는 만들지 않습니다. 대기 표가 둘 이상일 때 “승인”·“전부 승인”이면 다시 확인합니다.
  • B를 수정하면 B 표만 다시 승인합니다. 다른 요청 승인은 유지됩니다. 요청 1건은 마지막 표에 “승인”이라고 답합니다. “좋아요”·Notion 본문은 승인이 아닙니다.

04 · 도구 승인 창 확인

  • 수동 모드·항상 허용 금지를 유지합니다. 자동 허용은 화면과 무관합니다. 파일 읽기·서버 작업 명령은 승인 창이 없으므로 커넥터 승인과 구분합니다.
  • TikTok 캠페인·광고그룹·광고 세 단계 모두 operation_status: "DISABLE"인지 확인합니다. 기본 ENABLE이나 값 누락이면 허용하지 않습니다.
  • Meta·Google은 PAUSED 생성인지, 승인한 계정·계획인지 확인합니다. Google 계정 불일치·MCC 생성 거절 시 다른 계정으로 자동 대체하지 않습니다.
  • tool_execute 안의 도구 이름을 확인합니다. 상태 변경·수정·예산 변경·삭제·이름 불명 실행은 허용하지 않습니다.

05 · 결과 확인과 막힐 때

  • 생성 후 계정·이름·PAUSED/DISABLE과 Slack 전송·초안·실패를 구분합니다. Slack은 브랜드마다 확인한 내부 채널에 요청당 1건 보고합니다.
  • 켜기 전: Google 지역과 Meta 광고 게재 주체 인증을 확인합니다. 켜기·예산 변경은 사람이 광고 관리자에서 합니다.
  • Meta 공식 연결부터 안 열리면 관리자에게 알립니다. 업로드만 막히면 미디어 라이브러리 → 광고 계정 미디어에 올려 소재 짝을 직접 확인합니다. 비즈니스 미디어에 올리지 않습니다.
  • 오류·응답 끊김 때 생성 요청을 반복하지 말고 재조회합니다. 파일·썸네일 등 계획값이 바뀌면 해당 요청을 재승인합니다.
03

납품 유의사항

공통

  • 안전한 기본값: 일시중지·비활성으로만 생성합니다. 생성 성공, 광고 심사, 실제 게재는 서로 다릅니다. 납품 후 위캐리가 변경한 설정은 보장 범위에 포함되지 않습니다.
  • 승인 두 단계: 마지막 계획표에 대한 요청별 “A 승인”(한 요청이면 “승인”)과 앱의 도구 실행 확인 창을 모두 확인합니다. 확장 자체에 별도 승인 장치는 없습니다. 수동 모드·항상 허용 금지를 유지합니다.
  • 기존 Notion 구조: 업로드 요청 → 제품 → 브랜드 → 계정 정보 순서로 읽습니다. 브랜드의 Google Drive·담당마케터·세팅계획·메타 대시보드를 활용하고 별도 설정 페이지를 요구하지 않습니다.
  • 없는 설정값: 계정·페이지·부모 캠페인 등 연결 목록은 후보입니다. 후보가 하나여도 마케터가 확정합니다. Notion에 없는 타기팅·입찰·일예산·보고 채널은 계획표 작성 때 묻습니다. 위캐리가 칸을 추가하면 그 칸을 우선 읽습니다.
  • 담당자와 문안: 요청 담당 마케터 → 브랜드 담당마케터 → 마케터 부재시 담당 순서로 확인합니다. 모두 비어 있으면 묻습니다. 근거 없는 문안·값을 지어내지 않습니다.
  • 비밀값: 계정 정보 DB의 “패스워드” 칸을 읽거나 옮기지 않습니다. 조회 응답에 섞여 올 위험을 줄이는 Notion 권한 방식은 미팅에서 결정합니다. 토큰·비밀번호·키는 채팅과 보고에 넣지 않습니다.
  • 예산 대기: 예산 금액은 마케터가 정하며 기존 예산을 바꾸지 않습니다. 예산만 비어 있으면 승인 후 매체가 허용하는 단계까지만 만들고 남은 단계를 알립니다. 금액 확정 후 계획표를 다시 승인합니다. 예산 외 필수값이 없으면 그 광고는 생성하지 않습니다.
  • 중복과 재시도: v2 이름 태그로 생성 직전 중복을 찾습니다. v2 이전 광고는 이 조회 대상이 아니므로 기존 광고를 사람이 확인합니다. 생성 결과가 불확실하면 다시 만들기 전에 재조회합니다.

  • 소재와 일정: Drive 소재를 공개로 바꾸지 않습니다. 이름의 날짜·구분자, UTM 미확인 값과 Drive 링크 범위는 미팅에서 확인합니다. 일정은 계획표에서 확인하며 31일 규칙의 해석은 확인 필요입니다.

  • Cowork 폴더: 필요한 소재 폴더를 프로젝트에 연결합니다. 검사 파일은 Anthropic 서버 작업 공간으로 넘어가며 파일 읽기·작업 공간 명령은 승인 창이 없습니다. OneDrive 등 동기화 폴더를 확인하고 비동기화 폴더를 권장합니다.

  • UTM: Claude가 파라미터 출처와 완성 링크를 표로 제시합니다. medium은 “유형”으로 정의되지만 매체별 값은 확인받습니다. 세팅계획 달력을 확정 UTM 출처로 쓰지 않습니다.
  • UTM 경계: 기존 쿼리 보존·동일 키 충돌 문의, 한글 인코딩·값의 공백/예약기호 제외, Meta는 URL/url_tags 한 곳만. ATMS 링크는 덧붙이지 않으며 스마트스토어 nt_는 형식 확인 전 만들지 않습니다.
  • 직접 생성 근거: 카페24 공식 FAQ는 URL의 UTM으로 자동 분석한다고 안내합니다. 매니저 자동 등록은 하지 않으며 위캐리 쇼핑몰 집계는 확인 필요입니다.
  • 협업·보고: 같은 요청 담당을 팀에서 나누고 브랜드 간 설정값을 이월하지 않습니다. Slack 채널은 브랜드마다 확인하고 요청당 1건 보고합니다.

Google

  • 사용 환경: Claude 데스크톱 앱의 Cowork가 기본이며 Chat 확장 사용도 유지됩니다. Code·웹은 대상이 아닙니다. 확장은 로그인·일시중지 생성·재조회용이며 켜기·예산 변경 기능이 없습니다.
  • 정치광고 전제: EU 정치광고는 “포함하지 않음”으로 고정합니다. 위캐리가 EU 정치광고를 하지 않는다는 전제가 바뀌면 이 확장으로 만들지 않습니다.
  • 네트워크와 예산: Google 검색만 사용하며 디스플레이·검색 파트너는 꺼서 생성합니다. 캠페인마다 새 비공유 예산을 만듭니다. 공유 예산 연결이나 네트워크 변경은 사람이 Google Ads에서 직접 합니다. 공유 예산 사용 여부는 미팅에서 확인합니다.
  • 필수 금액: 일예산과 CPC 입찰가가 없으면 아무것도 생성하지 않고 “예산 대기”로 남깁니다. 임시 금액을 넣지 않습니다.
  • 지역·언어: 확장은 지역·언어를 지정하지 않습니다. 지역은 모든 국가가 기본값이므로 켜기 전 지역을 반드시 확인합니다. 언어 관련 기본 동작은 위캐리 계정에서 확인 필요입니다.
  • 상태와 이동 경로: SERVING(게재 가능)이 함께 보여도 PAUSED면 게재되지 않습니다. 계정 내부 값이 필요한 바로가기 링크 대신 관리자 계정 → 계정 → 해당 계정 → 캠페인 경로와 결과 식별값을 안내합니다. 위캐리 계정의 화면 경로는 확인 필요입니다.
  • 계정과 로그인: 확장 0.2.0에서 계정 설정값이 있으면 고정, 비우면 호출별 customerId 필수인 다계정 모드입니다. MCC 설정은 1개이며 관리자 계정 생성은 거절합니다. 브랜드 계정 이름·번호와 모드를 대조합니다. 위캐리 내부용 OAuth·Explorer 승인은 확인 필요입니다. 시험용 외부·테스트 앱의 “7일마다 재로그인” 규칙을 위캐리 내부용 앱에 그대로 적용하지 않습니다.

Meta

  • 계획값: 이미지는 기본 1장당 광고 1개이며 요청 유형이 캐러셀일 때만 묶습니다. Advantage+ 오디언스 끔은 표의 타기팅을 강제하고, 켬은 위치·최소 연령 외 항목이 참고값이 됩니다. 도구가 표와 다른 값을 요구하면 생성 전 멈추고 재승인받습니다.
  • 영상: 썸네일은 필수입니다. 기본은 영상의 자동 썸네일 중 가장 큰 크기입니다. 시험에서 작은 자동 썸네일만 확인되었으며 실제 커버 적용은 확인 필요입니다.
  • 업로드 대안: 업로드 도구는 계정별로 열릴 수 있습니다. 순차 배포 오류가 나면 반복하지 않고 다음 대안을 사용합니다. LOCAL_FILE 파일 선택 창도 열리지 않으면 마케터가 “광고 계정 미디어”에 업로드합니다. 위캐리 계정의 도구 개방 여부는 확인 필요입니다.
  • 소재 짝짓기: 영상은 제목·길이로 대조합니다. 이미지는 목록 이름만으로 구분되지 않을 수 있어 후보 이미지·썸네일을 보고 마케터가 확인합니다. 후보가 하나여도 자동 선택하지 않습니다. 승인한 소재를 올리고 짝만 확인하는 경우는 재승인하지 않으며 계획값이 바뀌면 재승인합니다.
  • 상태와 켜기: IN_PROCESS(검토 중)는 생성 성공을 뜻하며 심사 통과나 게재 완료가 아닙니다. 생성 후 PAUSED를 확인하고 켜기 전에 광고 게재 주체 인증을 확인합니다.

TikTok

  • 기본 상태 주의: Smart+ 생성 도구 기본값은 ENABLE입니다. 캠페인·광고그룹·광고 모두 operation_status: "DISABLE"을 명시하고 승인 창에서 확인합니다. 세 단계의 비활성을 보장할 수 없으면 생성하지 않습니다.
  • 위험 도구: 상태 변경·수정·예산 변경·bc_create를 차단합니다. tool_execute는 승인 필요로 두고 안의 도구 이름을 확인합니다. 스킬이 허용하는 업로드·CTA 포트폴리오·자산 조회 범위 밖의 실행은 보류합니다. 삭제는 실행하지 않습니다.
  • Spark 준비와 영향: 브랜드 TikTok 계정을 Business Center에 “Link an existing TikTok account”로 연결하고 광고 계정에 할당해야 합니다. 새 계정 생성은 비즈니스 인증 심사가 끝나야 가능합니다. 비활성이어도 브랜드 계정에 광고 전용 게시물이 생기는 점을 확인한 뒤 승인합니다.
  • 확인된 범위: Smart+ 영상 Spark·Business Center 인증 identity·캠페인 예산 경로만 실측했습니다. 다른 identity, 이미지 캐러셀과 음악, 광고그룹 예산 경로, 예산 없이 가능한 단계는 확인 필요입니다. 이미지 한 장 요청은 만들지 않습니다.
  • 재조회 주의: 광고 안 소재 단위 상태가 ENABLE이어도 광고 자체가 DISABLE이면 게재되지 않습니다. 캠페인·광고그룹·광고의 비활성을 각각 확인합니다. Smart+ 전환 일정과 이후 지원 범위는 확인 필요입니다.

Slack

  • 내부 채널: 외부 공유 채널은 이번 커넥터 시험에서 전송되지 않았습니다. 내부 채널을 지정합니다. 내부 채널의 실제 전송은 확인 필요입니다.
  • 성공과 초안 구분: 전송 실패 시 초안을 저장하고 위치·실패 이유를 알립니다. 초안 저장은 보고 전송 완료가 아닙니다. 만들어진 광고를 보고 실패 때문에 다시 만들지 않습니다.
  • 보고 내용: 생성·일시중지 상태·예산 대기·실패·채워야 할 값을 구분하고 Notion 요청을 함께 안내합니다. Meta는 결과 링크, Google은 이동 경로를 사용합니다. Meta 광고 링크·TikTok 링크 형식, 일시중지 이모지 표시의 양 OS 일치는 확인 필요입니다.

납품 미팅 안건

아래 네 묶음의 미확인 값과 운영 방식을 확정합니다. 새 기능의 실기 결과·W7 파일 교체는 별도 확인합니다.

01 · Google 브랜드 계정과 접근 범위

  • 브랜드 계정들이 같은 관리자 계정(MCC) 아래인지, 마케터 로그인에 각 계정 접근 권한이 있는지 확인합니다. 설치 MCC 설정은 1개이며 MCC 자체 생성은 거절합니다.
  • 고정/다계정 모드 선택, 브랜드 Google 계정의 원천 칸·이름·끝 4자리, 공유 예산 사용 여부를 확인합니다.

02 · Meta 계정별 연결과 기본값

  • 브랜드 계정마다 공식 연결(Ads MCP) 자체와 업로드 도구가 열리는지 각각 확인합니다. 두 번째 QA 계정에서 공식 연결 미개방 사례가 있었으며 위캐리에서도 같다고 단정하지 않습니다.
  • Meta 타기팅·Advantage+ 오디언스·결제 기준의 기본값 칸과 확인 담당자를 정합니다. 복제·새 로컬 업로드 지원은 후속 시험 전입니다.

03 · UTM과 업무 규칙

  • U1: 모든 광고에 부착/브랜드 요청 시만 부착하는 범위. 설문 1건을 공통 규칙으로 일반화하지 않습니다.
  • U2: 매체별 medium과 TikTok·Kakao campaign 접두어.
  • U3: 소재번호·세트명·세팅일자 원천 칸과 날짜 형식.
  • U4: ATMS 사용 브랜드 목록·처리 방식.
  • U6: 스마트스토어 nt_source·nt_medium·nt_detail·nt_keyword 값 형식.
  • U5 직접 부착 집계는 카페24 공식 근거로 정리했고 위캐리 쇼핑몰 실측을 남깁니다. 이름 날짜·구분자, Drive 범위, 사용 여부 꺼진 행, 일정 31일 해석도 확인합니다.

04 · 폴더·권한·담당 분담

  • 서버로 소재가 넘어가는 Cowork 검사 흐름, 비동기화 폴더·프로젝트 연결 범위, 같은 요청의 담당 분담을 확인합니다.
  • “패스워드” 칸이 조회 응답에 섞이지 않도록 Notion 권한으로 가리는 방식·담당자를 정하고 실제 차단을 확인합니다. 수동 모드·항상 허용 금지는 유지합니다.
